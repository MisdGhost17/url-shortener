# URL Shortener

Сервис сокращения ссылок на Go со страницей управления, статистикой переходов
и хранением данных в памяти. Внешних зависимостей нет; требуется Go 1.25.4+.

## Запуск

Из корня проекта:

```sh
go run ./cmd/server
```

Приложение слушает `:8080`. Интерфейс: `http://localhost:8080/`.
Данные теряются при перезапуске, как и в исходной реализации.

```sh
docker build -f dockerfile -t urlshortener .
docker run --rm -p 8080:8080 urlshortener
```

## Архитектура

Структура и соглашения взяты из локального `golang-todoapp`:

```text
cmd/server/main.go                         # ручная сборка Repository → Service → HTTP
internal/
  core/
    domain/url.go                         # сущность URL и её инварианты
    errors/common.go                      # ошибки, проверяемые через errors.Is/As
    codegen/random.go                     # криптографическая генерация кодов
    transport/http/
      middleware/                         # CORS и журнал запросов
      response/                           # JSON и преобразование ошибок в HTTP
      server/                             # Route и регистрация маршрутов
  features/
    urls/
      service/                            # сценарии и интерфейсы репозитория/генератора
      repository/memory/                  # потокобезопасное хранилище
      transport/http/                     # интерфейс сервиса, обработчики и DTO
    web/transport/http/                   # страницы, favicon и статические файлы
web/static/                               # исходный интерфейс без изменений
```

Интерфейсы принадлежат потребляющему слою: HTTP зависит от контракта сервиса,
сервис — от контракта репозитория. Конкретные реализации соединяются в
`cmd/server/main.go`. Домен не зависит от HTTP, хранилища или JSON.
Операции вынесены в отдельные файлы, пакеты и конструкторы названы по соглашениям
образца. HTTP DTO отделены от сущности. Для хранилища в памяти отдельная модель
БД не нужна: оно хранит копии значений домена и не выдаёт изменяемые ссылки наружу.

Создание проверяет уникальность и записывает ссылку под одной блокировкой.
При коллизии сервис генерирует новый код; отмена контекста останавливает повторы.
Чтение при переходе и увеличение счётчика также выполняются атомарно.
Обновление зависимостей не потребовалось: используется только стандартная библиотека.

## Совместимость API

| Метод | Маршрут | Результат |
|---|---|---|
| POST | `/api/shorten` | 201, `short_url`, `short_code`, `original` |
| GET | `/{shortCode}` | 302 на исходный URL, увеличение `clicks` |
| GET | `/api/stats/{shortCode}` | `short_code`, `original_url`, `created_at`, `clicks` |
| GET | `/api/list` | Массив статистики; пустой список — `[]` |
| DELETE | `/api/delete/{shortCode}` | 200, `{"message":"удалено"}` |
| GET | `/` | Главная страница |
| GET | `/static/…`, `/favicon.svg` | Статические файлы |

Создание принимает `{"url":"https://example.org"}`. Код состоит из шести
латинских букв/цифр. Формат ошибок — `{"error":"…"}` с прежними русскими сообщениями.

Для совместимости сохранены особенности исходного приложения:

- `short_url` использует `https://` и Host запроса. При локальном запуске без TLS
  для проверки перехода нужно открыть `http://localhost:8080/{shortCode}`.
- Отсутствующая короткая ссылка показывает `404.html` со статусом **200**;
  отсутствие записи в API статистики/удаления возвращает **404**.
- List и stats по-прежнему не ограничивают HTTP-метод.
- Валидация исходного URL проверяет непустое значение и префикс `http://`/`https://`.
- OPTIONS возвращает 200; CORS разрешает `*`, GET/POST/DELETE/OPTIONS и Content-Type.
- Порядок списка не определён.

## Проверки

```sh
make check
# Или отдельно:
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

Тесты проверяют жизненный цикл ссылки через HTTP, JSON и статусы ошибок,
статические страницы и CORS, доменную валидацию, коллизии кодов, ошибки генератора
и хранилища, отмену операций и конкурентное создание/подсчёт переходов.
HTTP-тесты также прогнаны на временной копии исходной реализации, чтобы
проверить сохранение контракта. Исходный проект не содержал тестов и Git-репозитория.
